# CRM для бизнеса (мультитенантная)

Одно приложение на много компаний-клиентов. Каждая компания получает своё рабочее пространство
со своими сотрудниками, воронками, этапами и дополнительными полями. Данные изолированы в базе
политиками Supabase RLS по `organization_id`.

## Что умеет
- Регистрация, вход, несколько рабочих пространств на одного пользователя
- Роли: владелец, администратор, менеджер, только просмотр; приглашения по ссылке
- Контакты (поиск, импорт CSV), компании
- Сделки на канбан-доске с перетаскиванием, несколько воронок, настраиваемые этапы
- Задачи и история (заметки, звонки, встречи, смена этапа)
- Дополнительные поля для контактов, компаний и сделок
- Сводка: сумма в работе, выиграно, сделки по этапам, просроченные задачи

## Стек
Next.js 16 (App Router, Server Actions) · TypeScript · Tailwind CSS 4 · Supabase (Postgres, Auth, RLS) · Vercel

## Запуск локально
```bash
cp .env.example .env.local   # URL и publishable key проекта Supabase
npm install
npm run dev
```

## База данных
Схема и политики применены миграциями в проекте Supabase `crm` (cpgdjxdpelwswdaiqheo):
`init_multitenant_crm`, `harden_helpers_and_same_org_refs`, `profile_email_and_owner_protection`,
`fix_check_same_org`, `guard_owner_allow_org_delete`.

Ключевые защиты:
- RLS на всех таблицах: читать могут только участники организации, писать — менеджеры и выше
- Триггер `check_same_org` не даёт ссылаться на записи чужой организации
- `organization_id` нельзя изменить после создания
- Роль владельца выдаёт и снимает только владелец; у организации всегда есть владелец
